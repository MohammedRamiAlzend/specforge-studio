# Success Metrics — SpecForge Studio

## 1. Metric List

| ID | Metric | Target (v1) | Why It Matters |
|----|--------|-------------|----------------|
| MET-01 | Time from spec entry to generated documentation | Minutes, not days | The core value: docs are generated, not written |
| MET-02 | Traceability coverage | 100% of REQs linked to UC/TASK/TC | Requirements must never orphan |
| MET-03 | Manual Mermaid edits | 0 for generated diagrams | Diagrams must be derived, not hand-maintained |
| MET-04 | Task pack execution success rate | ≥ 90% first-pass | Checklists must be concrete and executable |
| MET-05 | Approval cycle time | ≤ 2 working days per gate | Governance must not stall delivery |
| MET-06 | Doc–model consistency | 100% (docs regenerated from DB match) | DB is the single source of truth |
| MET-07 | Agent neutrality | Packs executable by ≥ 3 agent families unchanged | No vendor lock-in |
| MET-08 | Regeneration fidelity | Export → re-import round-trips without data loss | Hybrid storage must be reversible |

## 2. How They Are Measured

- MET-01: measured from the moment a project's structured model is complete to the first export.
- MET-02: computed by the traceability report (Prompt 08/10 tooling).
- MET-03: counted from audit records of generated diagram files.
- MET-04: reported by agents against task checklists (TASK/CHK).
- MET-05: recorded in approval records (APR).
- MET-06/08: verified by regeneration tests in Prompt 12.
- MET-07: verified by running a sample task pack with multiple agent families in Prompt 12.

## 3. Reporting

Metrics are reported in the traceability and validation reports generated by the system. They are not optional — they are part of the definition of done for each release of the platform.

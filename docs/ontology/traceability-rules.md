# Traceability Rules — SpecForge Studio

Every rule has an ID (TR-xx), a statement, and a verification method. The traceability report (generated by the system) checks these rules and flags violations.

## 1. Mandatory Rules

| ID | Rule | Verification |
|----|------|--------------|
| TR-01 | Every Requirement must link to at least one UseCase or Workflow. | Traceability report: REQs with no UC/WF link |
| TR-02 | Every Workflow must have exactly one start node and one end node. | Model validation on save; report |
| TR-03 | Every Workflow node must be reachable from the start node, and the end node must be reachable. | Graph traversal check in report |
| TR-04 | Every decision node must have success and failure branches (≥ 2 outgoing edges), each with a condition. | Graph validation on save; report |
| TR-05 | Every Entity must have exactly one primary-key field. | Model validation; report |
| TR-06 | Every ApiEndpoint must define input, output, and errors. | Schema validation on save |
| TR-07 | Every critical Requirement must have at least one TestCase. | Traceability report: critical REQs with no TC |
| TR-08 | Every Milestone must link to at least one Task (except a final milestone). | Report |
| TR-09 | Every Task must have an objective, at least one checklist item, and a definition of done. | Task validation on save |
| TR-10 | Every Approval must reference an artifact and a role with approval rights for that artifact kind. | Approval validation; governance report |
| TR-11 | No orphan references: every ID referenced by any entity must exist. | Referential integrity check in report |
| TR-12 | Every Artifact must record its generating source entities (`sourceEntityIds`) or be flagged as unlinked. | Report |
| TR-13 | Stable IDs must be preserved verbatim across database, Markdown frontmatter, Mermaid labels, and task packs. | Export diff test |
| TR-14 | Every generated document and diagram must declare its project and module origin. | Frontmatter check in report |
| TR-15 | Every Task must trace back to at least one Requirement, Workflow, Risk, or Decision (i.e., no invented work). | Report: tasks with no source link |

## 2. Recommended Rules

| ID | Rule | Verification |
|----|------|--------------|
| TR-16 | Every UseCase should link to at least one Screen or ApiEndpoint. | Report warning |
| TR-17 | Every Screen should be linked from at least one UseCase. | Report warning |
| TR-18 | Every Component should appear in at least one ArchitectureDiagram. | Report warning |
| TR-19 | Every Risk should have a mitigation or be explicitly accepted. | Report warning |
| TR-20 | Every approved Requirement should have at least one Task referencing it. | Report warning |
| TR-21 | Every cross-project workflow call (workflow_call node) must resolve to an existing workflow-kind graph of another project. | Report warning |

## 3. Traceability Report

The generated traceability report must include:

1. Rule-by-rule pass/fail status (TR-01 … TR-21).
2. Lists of violating entity IDs.
3. Coverage metrics per requirement (linked UC/WF/TASK/TC count).
4. Orphan and dangling-reference lists.

## 4. Enforcement

- Rules marked **mandatory** block phase completion when violated (see master prompt validation rules).
- Violations are recorded in memory as validation warnings and must be resolved before the affected phase is marked complete.

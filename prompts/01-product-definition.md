## Objective

Define the product clearly before any implementation.

## Deliverables

Create or update the following files:

- docs/product/PRD.md

- docs/product/non-goals.md
- docs/product/user-roles.md
- docs/product/success-metrics.md
- docs/product/open-questions.md

## Requirements

The PRD must describe:

1. What SpecForge Studio is
2. Who uses it
3. The main problem it solves
4. The core workflow
5. The major modules
6. The input model
7. The generated outputs
8. The agent execution behavior
9. The approval and governance behavior
10. The hybrid storage behavior

## Product Principles

The product must be defined as:

- an internal engineering platform
- a full software lifecycle management system
- a visual spec engine
- a Markdown documentation generator
- a roadmap planner
- an agent task packaging system
- a traceability and governance system

## Mandatory Product Constraints

Include these constraints in the product definition:

- English-only generated artifacts
- database as source of truth
- Markdown as export/output format
- agent-neutral task packs
- executable checklists
- human approval gates plus automation
- no external integrations in v1
- support for web, mobile, API, and AI projects
- support for projects built from scratch
- support for workflow, sequence, ERD, and architecture diagrams
- no manual Mermaid writing by the end user

## Style Reference

Use the provided handoff knowledge base as a style reference for documentation quality:
- numbered documents
- clear reading order
- open points
- agent guide
- practical developer handoff style
